# Overview

Runtime Frameworks define how enterprise capabilities are executed, coordinated and managed within the HoldCo Digital Enterprise Ecosystem.

While Enterprise Frameworks establish governance and Engineering Frameworks define development methodologies, Runtime Frameworks provide the execution environment responsible for operating enterprise platforms, services, products and Hybrid Classical + Quantum AI (QAI) workloads.

Runtime Frameworks form the operational foundation of the future Enterprise Operating Platform (EOP) and QAI CoreOS.

I think this is one of the most strategic documents because it bridges the architectural work we've done with the future QAI CoreOS implementation.

One distinction I recommend making is:

Engineering Frameworks → How systems are engineered.
Enterprise Operating Platform (EOP) → How the enterprise is managed.
Runtime Frameworks → How enterprise capabilities execute at runtime.

This document should therefore focus on execution, not design.

Architectural observation

I think we've now reached the point where the Enterprise Operating Platform (EOP) can be viewed as three complementary layers:

```
Enterprise Operating Platform (EOP)

├── Enterprise Frameworks
│      Defines WHY and WHAT
│
├── Engineering Frameworks
│      Defines HOW systems are built
│
├── Runtime Frameworks
│      Defines HOW systems execute
│
└── QAI CoreOS
       Implements the runtime architecture
```
This aligns closely with the earlier GitLab workspaces you've shared—particularly the QAI Base Platform, FAEP Ecosystem, HoldCo Factory, and the multi-control-plane architecture. Those earlier designs become concrete implementations, while the HoldCo repository defines the architectural contracts that guide their evolution. I think this layered separation will make the transition into QAI CoreOS development much cleaner because each layer has a distinct responsibility within the overall enterprise architecture.
